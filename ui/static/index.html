A deadlock detector you can watch work

Two threads, two locks. Thread P takes lock A and then B; thread Q takes B and then A. Most of the time they miss each other and the program is fine. Once in a while both grab their first lock at the same moment, and then each waits for the other forever. Tests rarely catch this because it depends on timing.

LockSpy sits between the program and the pthread library (via LD_PRELOAD, so no recompiling) and keeps track of which thread holds which lock. It looks for two things:

  1. a cycle in the lock order: somewhere A was taken before B and somewhere else B before A. That's a Potential deadlock, even if this run got lucky.
  2. threads that are actually stuck waiting on each other. A watchdog checks every half second; if it finds a cycle, that's a Live deadlock.

For each one it says which lines took the locks and what order to use instead.

The tests below run by themselves when the page loads. Click any program to see its lock graph, the report and the lines involved; ab_ba and philosophers_naive are good ones to start with. Turn on Naive mode and re-run a tricky program to see the false alarms LockSpy normally filters out. If the idea is new to you, the Learn page walks through it step by step.
