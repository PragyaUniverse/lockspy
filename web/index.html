Runtime deadlock detector · C/C++ · Linux

Find the deadlock before it hangs.

LockSpy loads into any unmodified pthread program with LD_PRELOAD. It watches every lock call, warns when two code paths take locks in opposite orders, catches the hang when it really happens, and tells you which lock order fixes it.

./bin/lockspy run -- ./build/tests/buggy/ab_ba
No recompile 0 false alarms on 16 test programs ~185 ns per uncontended lock

How it works

Sit between the program and libc

The dynamic linker searches LD_PRELOAD libraries first, so the program's pthread_mutex_lock calls land in LockSpy. Each wrapper records the event, then calls the real function found with dlsym(RTLD_NEXT).

Intercept

interpose.cpp

Wraps mutex, rwlock, condition-variable, semaphore and thread calls. Tries the lock first, so free locks cost one short bookkeeping step.

Record

recorder.cpp

Keeps each thread's held-lock set, thread names from /proc, and checks for relock, bad unlock and locks held at exit.

Analyse

lock_graph.cpp · waitfor.cpp

Edge H → L when L is requested while H is held; DFS finds cycles. A watchdog thread checks the live wait-for graph every 500 ms.

Report

report.cpp · symbolize.cpp

Names locks and call sites (forks[3], worker_q() (ab_ba.cpp:32)) and writes text, JSON, a Graphviz heat map and HTML.

What it catches

Real bugs flagged, safe patterns left alone

Reported

  • POTENTIAL DEADLOCK

    Locks taken in inconsistent orders, even if this run didn't hang.

  • LIVE DEADLOCK

    Threads stuck in a wait-for cycle right now. Optionally abort().

  • RELOCK

    Locking a non-recursive mutex the thread already holds.

  • BAD UNLOCK

    Unlocking a mutex the thread does not hold.

  • HELD AT EXIT

    A thread returns while still holding a lock.

Suppressed as safe

  • GATE LOCK

    Both orders happen under a common lock G, so they can never overlap.

  • TRYLOCK BACK-OFF

    A trylock never blocks, so it adds no edge (the Linux lockdep rule).

  • SINGLE THREAD

    One thread takes both orders; a deadlock needs at least two.

  • READ-READ

    Readers of a rwlock never wait for each other.

  • CONDITION WAIT

    pthread_cond_wait releases the mutex while sleeping; LockSpy mirrors that.

Slowdown, geometric mean over 6 programs

Where LockSpy loses: on a tight loop of uncontended locks in 4 threads, ThreadSanitizer was faster (2.6× vs 6.8×), because LockSpy sends every thread's lock events through one private lock. On the other five programs LockSpy was faster. Full tables: results/RESULTS.md.
